# CS 465 Full Stack Development Reflection

## Architecture

Throughout the Travlr Getaways project, I worked with multiple approaches to frontend development, including Express HTML, JavaScript, and an Angular single-page application (SPA). The customer-facing portion of the application uses Express with server-side routing and templates to generate pages for the user. In this approach, the server receives a request, processes the request through the appropriate route and controller, and returns the rendered page to the browser. JavaScript provides additional logic and interaction within the application.

The administrative side uses Angular as a single-page application. Unlike the traditional Express approach, Angular organizes the frontend into reusable components, services, models, and routes. Once the SPA is loaded, Angular can update portions of the interface without requiring a complete page reload. For example, the administrative trip listing is created from reusable trip components and receives trip information through the REST API. This separation allowed the customer-facing website and administrative interface to use the same backend data while providing different user experiences.

The backend uses MongoDB, which is a NoSQL document database. MongoDB was appropriate for this project because the trip information can be represented naturally as document-based data. Instead of requiring the rigid tables and relationships commonly associated with a relational database, MongoDB stores documents with fields such as the trip code, name, length, resort, price per person, image, and description. Mongoose provides the application with a schema and model layer for interacting with MongoDB.

## Functionality

JSON and JavaScript are related, but they serve different purposes. JavaScript is a programming language used to create application logic, while JSON is a text-based data-interchange format. JSON represents information using key-value structures that can be transmitted between different parts of an application. In Travlr Getaways, JSON connects the frontend and backend by providing a common representation of trip data. The Express REST API can return trip information as JSON, and the Angular application can receive that response and convert the information into objects that its components can display. When an administrator makes a change, information can also be sent from Angular to the API in the request body.

Refactoring was an important part of developing the application. One example was separating database access from the user interface by moving trip operations into REST API endpoints and having the frontend request data from those endpoints. Another example was the Angular administrative interface. Instead of creating separate duplicate markup and logic for every trip, I used reusable components such as the trip card and trip listing. Services were also used to centralize operations such as retrieving trip data and authentication.

Reusable UI components provide several benefits. They reduce duplicate code, make changes easier to maintain, and help create a consistent interface. If the presentation of a trip needs to change, the reusable trip component can be modified instead of changing every individual trip. Separating API communication into services also keeps networking and data-access logic out of the visual components. This makes the application easier to understand, test, maintain, and expand.

## Testing

Testing the Travlr Getaways application required understanding HTTP methods, API endpoints, database operations, and security. An endpoint identifies a particular resource or operation exposed through the API, while the HTTP method communicates what action should be performed. For example, GET requests retrieve trip information, POST requests create resources, PUT requests update existing information, and DELETE requests remove information.

During development, I tested the trip API to verify that the application could retrieve trip information from MongoDB. The `/api/trips` endpoint returned the collection of available trips, while individual trip requests could retrieve specific records. I also tested the administrative application by creating a test trip, modifying its information, and deleting it. These tests helped verify that the Angular frontend, Express API, Mongoose models, and MongoDB database were communicating correctly throughout the CRUD process.

Adding authentication introduced another layer of testing. The application uses an administrator login and JSON Web Tokens (JWTs) to distinguish authenticated requests from unauthorized requests. I tested registration and login through the authentication API and confirmed that successful authentication returned a token. I then verified that the Angular administrative interface could authenticate the user and provide access to its protected functionality.

Security also changes how API endpoints must be tested because a request can be structurally correct but still be rejected when the required authorization information is missing. For example, I tested a protected DELETE request without an authorization token and received an HTTP `401 Unauthorized` response with a message indicating that an authorization header was required. This demonstrated that the protected endpoint was not allowing an unauthenticated client to perform the operation. Testing a secured full stack application therefore requires checking not only successful requests, but also expected failures such as missing credentials, invalid credentials, invalid resources, and unauthorized requests.

## Reflection

This course helped me develop a much stronger understanding of how the individual technologies used in web development work together as a complete software system. Before completing the Travlr Getaways project, it was easier to think about frontend development, backend development, APIs, and databases as separate topics. Building the application from beginning to end helped me understand the complete request and data flow between the browser, frontend, REST API, server-side logic, Mongoose models, and MongoDB database.

I also gained practical experience with technologies and concepts that are valuable for software engineering positions. These include Node.js, Express, Angular, MongoDB, Mongoose, REST APIs, JSON, CRUD operations, component-based development, routing, authentication, JWTs, and Git/GitHub version control. I also gained additional experience troubleshooting a full stack application because problems could originate from several layers, including the frontend, API routes, authentication logic, environment configuration, server, or database.

The project strengthened my understanding of secure application development as well. Adding authentication demonstrated that application security is not simply a login page. The frontend must manage authentication state, the client must provide the appropriate token with protected requests, and the backend must independently verify authorization before allowing administrative operations.

These skills make me a more marketable software engineering candidate because I can discuss and demonstrate experience building a complete application rather than only isolated programming exercises. The completed Travlr Getaways application demonstrates my ability to work across the software stack, connect a frontend to a RESTful backend, persist information in a database, implement authentication, test functionality, troubleshoot integration problems, and organize a larger project using reusable and maintainable components. The project also gives me a concrete example that I can use when discussing full stack development, APIs, databases, security, and software architecture with future employers.
